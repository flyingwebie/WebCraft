# One building area on the Site's own address, with the page in a same-origin frame

Status: Proposed. Nothing is built yet; the order of work is in the UI overhaul's plan.

Edit mode, Code mode and the Builder become one **building area**: one full-screen shell with a rail, a canvas, docks holding movable panels, a bottom bar, and places (Content, Templates, Media, Styles, Loops, Components, and behind "more" Forms and what Modules add) that open over the canvas without leaving it. The Site's own address serves it (its verified Primary domain, else its Staging address) at `/_webcraft/build/…`, and it shows the page in a frame of the same origin: the page at its own path, rendered for the person editing. Because the frame is same-origin, the shell reads the page's elements directly and draws selection, outlines and chips over it, as the Builder's canvas already does for its preview, and it gives the page a real width, so the Site's media queries answer at tablet and phone widths. We chose this because three editors with three kinds of chrome could not be told apart or left, moving between them reloaded the page or changed host, and a page narrowed inside a wide window is not a device preview. A shell that stays loaded also makes one Undo history and one set of live Drafts the natural state, not something handed from page to page.

## What is decided

- **Who gets in, and how.** As today (ADR 0022): a one-use link from the admin (`editMode.open`) starts an Edit mode session on the Site's address, tied to the admin session, for at most 8 hours, and every request is checked again (the edit cookie, the header token, the Site's own origin). There is no second sign-in, and the admin's cookie never reaches a Site. The link also names what to open and the admin screen to go back to. The admin has one address that makes such a link and follows it, so every admin screen that opens the building area is a plain link.
- **One shell, drawn by Permission** (ADR 0028). With `structure.edit` a person gets the whole building area. Without it they get client editing: the same shell larger and in words, with no code panes, Inspector, Layers tree, insert row, or Templates, Styles, Loops and Components places, and Sections only where the Site lets Members arrange Page layouts. The server decides every request by `can()`; the shell only leaves out what the person may not do.
- **What runs where.** The shell is WebCraft's own code only: hashed files on the Site's domain, a policy of its own (`script-src 'self'`, nothing inline, framed by nobody). It loads none of the Site's scripts. The framed page runs what Edit mode runs today, the Site's own scripts and Libraries and never an outside script, plus one WebCraft script first in its head, the page agent: it keeps the browser functions it needs before any Site script runs, makes Content editable in place, catches the page's errors, tells the shell when the frame shows another page, and sends a page opened outside the frame into the shell. Everything with chrome (panels, toolbars, popovers, chips, outlines) and every service (requests, shared Drafts, the Undo history) lives in the shell.
- **The frame's headers.** A page rendered for editing may be framed by its own origin only (`frame-ancestors 'self'`, `X-Frame-Options: SAMEORIGIN`), as visitors' pages already may; today it may be framed by nobody. This gives nothing away: a script of the same origin already reads the page and the session's header token with a plain request. The rest of Edit mode's policy stands.
- **What a page shows.** For someone with `structure.edit`, the Drafts of the Site's Structure around the Drafts of its Content, with every element tagged with where it comes from (Code mode's tags) and every editable region tagged too, in the same render, so one click selects and, on text, starts typing. Today the renderer writes one kind of tag or the other; it will write both. For everyone else, the Drafts of the Content through the published Structure, as Edit mode shows it today: Members never see a half-made Template.
- **A Template or Component with no page to show it** opens on a stand-in: its tree rendered by the Builder's preview (preview data, no scripts) in the same frame and shell. Where a page shows it, it opens on that page.
- **What the session reaches.** The page's own edit requests (`/_webcraft/edit/api/…`: the page state, text, images, Loop items, Page details, Publish and Review of the page) stay as they are. Everything else the shell needs is the Management API itself, served on the Site's address for the edit session as if it were an API client (the way API tokens already call it without a session cookie): only the procedures on a named list, only on the session's Site, as the person, recorded as coming from Edit mode. Workspace, Install and account procedures are not on the list (apart from the person's own editor preferences), and a Sensitive action is always refused there. Code mode's own copies of these services (`code/…`) go once the shell no longer calls them.
- **Addresses.** The open document is the path: `/_webcraft/build/page/<path on the Site>` for anything that has a page (a Page, an Entry, an archive, search results), and the Builder's targets for the rest (`/_webcraft/build/site-template`, `…/search-template`, `…/entry-template/<Post Type id>`, `…/archive-template/<Post Type id>`, `…/component/<id>`, `…/form/<id>`), with the Entry a Template previews as `?entry=`. An open place is `?place=` (`?place=styles/classes`) and the selection `?select=`, replaced rather than added. Back closes a place or returns to the document before; a reload opens the same document, place and selection. A link followed inside the frame opens that page as the document.
- **Drafts, Publish, Co-editing.** Drafts save as they change; there is no Save button. Every Draft the open document touches is opened once, as a shared document (ADR 0025), by the shell, over the co-editing sockets the Site's address already serves. Publish in the bottom bar publishes the open document's changed items, its Content and, for those who may, the Structure it shows, in one step, through the same procedure as Publish all. Presence shows by name on the page and in the tree.
- **One Undo history** (ADR 0036) lives in the shell for the life of the tab, across documents and places, and covers what a person changes in a place too. Since the shell is never left, nothing is handed over between pages or hosts any more.
- **Panels and docks.** Each panel has a switch and a rule about what must be open or selected for it to show; both must hold. A person's panel layout and their other editor settings (format when leaving a code box, the first-visit card seen) are kept with their account, like their admin theme, so they follow them to another browser and another Site.
- **Code panes** follow the selection: the Template markup of the Template or Component the selection comes from (for a Placement, its Props as markup), the CSS of the element's Classes, and the page's, the Site's or the Component's script. Format runs in the browser: the formatter is served from the Site's address and loaded the first time it is used.
- **Window widths.** For Staff the editor's width rule stands (docks from 1280 px, drawers from 1024 px, a covering notice below); client editing works at every width, with its own phone layout.
- **Leaving.** The logo tile goes back to the admin screen the person came from, keeping the session; Exit ends the session and goes there too.

## Considered Options

- **The shell on the admin, the Site's page in a frame from the Site's address.** The strongest separation, and the option ADR 0022 already rejected: the two are different origins, so every outline, drag and in-place edit becomes messages between frames, and the page still needs its own edit session to show Drafts.
- **The shell on the admin, with a copy of the page served from the admin.** Same origin, but the Site's own scripts and Libraries would then run beside the admin session, which reaches every Workspace the person can, or would have to be stripped, and then it is not the page. Every address the page names would also need rewriting. The Builder's canvas works this way for one tree with no scripts; it does not stretch to real pages.
- **Keep editing in the page and draw a frame around it.** The least work, but the window stays wide, so media queries never answer, and the editor's chrome keeps sharing a page with the Site's CSS and scripts.
- **Keep the Builder beside the shell for things with no page.** Two tools again, the drift ADR 0035 wanted to stop. The stand-in gives the same canvas inside the one shell.
- **Messages between the shell and the frame (postMessage) although they share an origin.** Would let the frame move to another origin later, but every hover, outline and caret position would go through a protocol for no gain today; the page agent keeps the frame's side small instead.
- **Serve the whole Management API on the Site's address.** Simpler than a list, but the Site's own scripts and Libraries run beside the shell with the same session, and could then reach Members, domains, secrets and other Workspaces.
- **Grow the hand-written edit requests to cover the places.** Keeps one transport, but copies dozens of procedures that already exist, with their checks, and every later change to one would have to be made twice.
- **A sign-in of its own on the Site's address.** A second place to hold passwords and second factors, on a domain the client owns.

## What it changes in earlier decisions

- **Supersedes ADR 0035** (one editor with two canvases): there is one canvas, a frame, and two things it can show (a real page, a stand-in). "Open in builder" and "View on a page" become opening another document in the same shell.
- **Amends ADR 0016** (Code mode): there is no Code mode to switch on and no reload into it. The code panes are panes of the bottom dock that follow the selection, still for Staff and the Superadmin only, still saving to the Drafts.
- **Amends ADR 0022** (scripts in Edit mode): Edit mode no longer runs "in the same page as the Site" but in a frame of the same origin under a shell on the Site's domain. Which scripts run, Safe mode and the request checks all stand. Same origin means the Site's own scripts can still reach what the session reaches, as today, and that reach grows to the listed procedures on this one Site.
- **Amends ADR 0023** (strict policy): the shell is one more set of hashed files on the Site's domain, with a policy of its own and nothing inline. Pages rendered for editing may be framed by their own origin.
- **Amends ADR 0002** (built in the admin): Templates and Components are built in the building area, on the Site's address, and are still stored as element trees.
- **Amends ADR 0036** (one Undo history): the hand-over between pages and between hosts goes; the history also covers what a person changes in a place.
- ADRs 0009, 0013, 0014, 0017, 0025 and 0028 stand as they are and bind the building area.

## Consequences

- Building needs an address. Today the Builder works for a Site with neither a verified domain nor a Staging address; the building area does not, as Edit mode never did. An Install that builds Sites must have its sites domain set, and the admin must say so where it is missing.
- A Site's own script or a Library running in the frame can call anything on the list for that Site, as the person editing. The list, the pin to one Site and the refusal of Sensitive actions are the boundary, and each addition to the list is a reviewed change with a test. Safe mode stays the way in when a script misbehaves.
- The editing bar, Code mode's injected parts, the live panels' Site-host mount, the admin's Builder route and canvas, and the Undo history's hand-over are deleted once the building area does what they did. Until then they run beside it, unchanged, and the building area is opened only where a ticket says so.
- The glossary needs the new words (building area, place, dock, panel, page agent, stand-in) and loses or redefines Edit mode, Code mode, Builder and Page layout drawer. "Edit on site" stays the way in from the admin, and the Audit log keeps naming the way in as Edit mode.
